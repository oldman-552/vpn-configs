# تقييم الكود + الاقتراحات

**التقييم العام: 5.5 / 10** — الفكرة واضحة والكود "يشتغل"، لكن فيه أخطاء منطقية تخسّرك **معظم** الكانفيغات بصمت، ومشاكل أداء/ثبات تمنعه من العمل كـ Cron كل ربع ساعة.

الخلاصة برقم: على 8 قنوات حقيقية، كودك الأصلي جمع **63** كانفيغ، والنسخة المحسّنة جمعت **333** من نفس الصفحات (≈ 5 أضعاف)، وبعض الكانفيغات التي جمعها كودك كانت **نصوص مكسورة غير قابلة للاستخدام** (إثبات أدناه).

---

## 1) أخطاء حرجة (تخسّرك كانفيغات)

### 1.1 الخطر الأكبر: `split("vmess://")` و `split("vless://")` — يُتلف الكانفيغات

```python
for part in vmess_parts + vless_parts:      # ← هنا المشكلة
```

`split` **ليست** استخراجًا: هي تقطيع. النتائج الفعلية على صفحة حقيقية (رسالة فيها `<code>` يحوي 3 كانفيغات):

| المُدخل | ما يخرج من كودك |
|---|---|
| `vless://A...#1` | `vless://A...` ✅ |
| `vmess://X...\nvless://B...#2\nss://C...#3` | `beyJhZGQ...` ❌ (بدون `vmess://`) + `...reality\nvless://B...` ❌ (مكسور) + `vmess://X...\n` ❌ (فيه سطر جديد) |

النتيجة: أول كانفيغ فقط ينجو، والبقية تخرج بلا اسكيم أو بلاصق نصّي. لذلك ستجد في ملفك أسطرًا لا يعملها أي تطبيق.

**الإصلاح:** استخدم regex على النص كاملًا، لا `split`:

```python
CONFIG_RE = re.compile(r"(?:vless|vmess|trojan|ss|ssr|hysteria2|hy2|tuic)://[^\s<>\"'`]+")
configs = CONFIG_RE.findall(block.get_text("\n"))
```

### 1.2 الاعتماد على `<code>` وحدها + `find_all` يُعيد الكتلة كاملة

كثير من القنوات ترسل الكانفيغ في:
- `<pre>` بدون `<code>`،
- نص عادي داخل `div.tgme_widget_message_text`،
- داخل `href`.

كودك يفوتها كلها. مثال مقاس: `t.me/s/i10VPN` → كودك **0** كانفيغ، والصحيح **105**. و`hopev2ray` → 7 مقابل 79.

**الإصلاح:** خُذ نص `div.tgme_widget_message_text` بالكامل + فحص روابط `<a>`.

### 1.3 لا شيء يُنظَّف قبل `split`

`code_tag.text.strip()` فقط، بلا حذف `#existing-remark` ولا تنظيف `&amp;` المتبقية. ثم في مرحلة لاحقة تعمل `split("#")[0]` **بعد** التقطيع، أي بعد أن تكون البيانات تضررت أصلًا.

### 1.4 الكود غير قابل للتشغيل تكرارًا (idempotent) ولا يعالج الأخطاء

```python
response = requests.get(url)      # بلا timeout، بلا status check، بلا retry
```
- أي قناة بطيئة أو محجوبة تُعلّق الحلقة كلها إلى الأبد (بلا `timeout`)، وهذا مؤكد عمليًا مع قنوات إيرانية محجوبة/rate-limited (429).
- إذا فشل 200 قناة، تُكتب `config.txt` **فارغة أو ناقصة** بلا أي تحذير → تدمير آخر نسخة سليمة عند التشغيل الدوري.
- ليست تسلسلية فقط بل بطيئة: 277 قناة تعني انتظارًا طويلًا.

**الإصلاح:** `timeout=(5,15)`, retry مع backoff, `Session` + `ThreadPoolExecutor`, وكتابة **ذرّية** إلى ملف مؤقت ثم `replace`، مع رفض الكتابة إذا كانت القائمة فارغة.

## 2) أخطاء متوسطة

| # | المشكلة | التفصيل |
|---|---|---|
| 2.1 | **حذف التكرار خاطئ** | `list(set(codes))` يخسر الترتيب، ثم `remove_duplicates` بـ O(n²) على ~4000 عنصر. استخدم `dict.fromkeys()`. |
| 2.2 | **التكرار المزدوج بلا معنى** | الحلقة الثانية (`new_processed_codes`) تكرّر الحلقة الأولى حرفيًا. أزل واحدة. |
| 2.3 | **`service_name` محسوب ولا يُستخدم** | `service_name = part.split("serviceName=")...` غير مستخدم أبدًا → تشويش وإبطاء. |
| 2.4 | **`#` يُقصّ قبل الكانفيغ الصحيح** | في `vmess://` بعض القنوات تضع base64 يحتوي `#`؛ قصّه قد يُنتج كانفيغ ناقص. الأفضل: `re.sub(r"#.*$", "", cfg)` على الكانفيغ المستخرَج فقط (كما في النسخة الجديدة). |
| 2.5 | **الاسكيم غير مدعوم كاملًا** | تُهمل `hysteria2`, `tuic`, `ssr`, `hy2` — وهي شائعة جدًا اليوم (وجدت 47 منها في تشغيل واحد). |
| 2.6 | **`jdatetime` بلا `try/except`** | إذا لم يكن مثبّتًا يسقط السكربت كله بعد أن أنجز كل الجمع. |
| 2.7 | **`unless` / منطق الـ remarks مرتبك** | `config_string` يُعاد تعريفه مرتين، والفرع `if i == 0` يخصّ أول كانفيغ فقط بذكر "تحديث كل ربع ساعة"، لكن **لا يوجد شيء في الكود يجعله يعمل كل ربع ساعة** — يجب أن يكون ذلك في `crontab`. |
| 2.8 | **لا تحقّق من صحّة الكانفيغ** | لا شيء يمنع الأسطر المبتورة (`vless://...` بلا `@host:port`). استخدمت شرطًا بسيطًا: `needs_at` للبروتوكولات النصية. |
| 2.9 | **قائمة القنوات مكرّرة** | 279 مدخلًا → 277 فقط فريد. أخرجها إلى `channels.txt` (خاصة وأن `XpnTeam`, `lightning6`, `icv2ray` مذكورة مرتين، و`https://t.me/s/v2rayNGcloud` مرة بـ `/s/` وأخرى بدونه). |

## 3) الاقتراحات (مرتبة بالأولوية)

1. **احفظ الروابط بشكل صحيح لتطبيقك**: الكانفيغات تُقصّ لتُبنى الـ remarks من جديد — هذا جيد، لكن يجب أن يُبنى على كانفيغ **سليم** مو على نتيجة `split`. ✳️
2. **أضف تحقّق TCP سريع (اختياري)**: فحص `connect()` على المضيف/المنفذ مع مهلة 2 ثانية، ثم اكتب فقط الكانفيغات الحيّة. عندي مثال لذلك جاهز لو أردت.
3. **لا تكرّر نفس الـ `remark`**: استخدم اسم القناة المصدر في الـ remark بدل رقم تسلسلي، فيصير من السهل معرفة أي قناة تنتج كانفيغات تعمل (وبالتالي تحذف القنوات الميتة).
4. **أخرج نسخًا متعددة**: `config.txt` (قائمة عادية) + `base64.txt` (الملف كامله base64 كتنسيق اشتراك شائع) + `singbox.json`/`clash.yaml` لو أردت.
5. **حافظ على سمعة IP الخاص بك**: `User-Agent` واقعي، `workers` معقول (8–10)، و`--limit` لعدد القنوات. Telegram يحجب بسرعة عند 429 إذا أطلقت 50 طلبًا متوازيًا.
6. **سجّل (logging) بدل `print`**: لتعرف كل دورة كم قناة نجحت وكم فشلت — مهم جدًا عند التشغيل في `cron`.
7. **جدولة بدل "ربع ساعة" في النص**:
   ```cron
   */15 * * * * cd /path/to/telegram-scraper && /usr/bin/python3 collector.py -o /var/www/html/config.txt -w 8 >> scrape.log 2>&1
   ```
8. **احترم شروط الخدمة والقوانين المحلية**: جمع كانفيغ VPN من قنوات عامة قد يخالف ToS أو قوانين بلدك؛ مسؤوليتك أن تتحقق قبل النشر العام.

أهم فرق عملي داخل الدالة الجديدة:

```python
def extract_configs(html: str) -> list[str]:
    soup = BeautifulSoup(html, "html.parser")
    blocks = soup.select("div.tgme_widget_message_text") or [soup]
    found = []
    for block in blocks:
        found += CONFIG_RE.findall(block.get_text("\n"))        # النص كاملًا، كل الكانفيغات
        for a in block.find_all("a", href=True):                # روابط أيضًا
            found += CONFIG_RE.findall(a["href"])
    return found
```
